## run .tlv4-v49-subquery-decompose (run: 2026-06-15)

- `_should_skip(node)` (`mcp_trino/trino_optimize.py`) ascends `node.parent` chain checking `{Exists, In, CTE, Union, With}` — used symmetrically by both `_extract_fragments` (extract side) and `_apply_rewrites` (apply side) to maintain ordinal symmetry (I3 invariant); adding a new extraction scope must add the corresponding `_should_skip` call on the apply side or ordinals will drift.
- `_pred_ordinal` (extraction) and `_subq_ordinal` (apply) are local monotonic counters in `_extract_fragments` and `_apply_rewrites` respectively; they must share identical TICK-CONDITION logic (same node classes, same `_should_skip` filter, same Subquery-wrapper guard for In) — breaking symmetry silently misroutes rewrites to wrong WHERE positions.
- TICK-CONDITION (§4.3.1): value-list `IN` (no `query` arg, or `query` arg not a `Subquery`, or `q.this is None`) produces NO fragment and NO ordinal tick on both extract and apply sides; only `IN (SELECT ...)` (Subquery-wrapped) ticks and extracts.
- `_is_correlated_exists(inner_select, cte_names)` uses Method A: inner FROM/JOIN tables collected via `inner_select.args.get("from_")` (underscore key — `"from"` returns None); `col.table` is a string property (not an `Identifier` object); CTE-alias check: `inner_tables & {n.lower() for n in cte_names}`; fail-conservative (returns True on any exception).
- `_assign_subq_ordinals` is a retained API stub (no-op); ordinals for role=subquery fragments are assigned inline in `_extract_fragments` via `_pred_ordinal`; the post-pass function is a no-op for API stability (spec §3.4).
- `_skip_subq_pass` guard in `_apply_rewrites`: when both `__root__` and any `__subquery_N__` key are present in `active_rewrites`, the entire subquery-ordinal branch is skipped (I5 / TR-COLL) — the tree was already re-based on the root rewrite so original ordinals are stale.
- Subquery kinds shipped in v49: WHERE EXISTS, WHERE IN (subquery). Out of scope and not extracted: derived tables (FROM subquery), UNION arms, scalar subqueries (SELECT-list), correlated subqueries are extracted but not cost-read (`is_independently_runnable=False`).
- `_apply_rewrites` recompose for Exists: `node.set("this", repl)` where `node` is the `Exists` AST node and `repl` is a bare `Select` (unwrap any `Subquery` wrapper first); for In: `q.set("this", repl)` where `q = node.args.get("query")` is the `Subquery` wrapper.
- The `continue  # NEUTERED` anti-pattern (early continue that kills an entire if-branch body without executing the intended work) was the root cause of the v49 deliverable gap; grep for bare `continue` lines inside `if node_class == "<type>":` branches when auditing future extract/apply loops.

## run .tlv4-v51b-decorrelate (run: 2026-06-16)

- `_sound_equi_corr_pairs(exists_node)` is the complete safe-class predicate for the proven-safe EXISTS→IN rewrite; conditions C0–C6c: C0 (caller ensures exp.Exists), C1 (positive EXISTS only), C2 (not inside OR), C2b (no OR in inner WHERE), C3 (exactly one correlated eq-pair), C4 (no aggregates), C5 (no DISTINCT/GROUP BY/HAVING/ORDER BY/LIMIT/OFFSET), C5b (no CTE/WITH in body), C5c (no JOINs in body — conservative single-table-only), C5d (no TABLESAMPLE — non-deterministic sampling), C6 (exactly one correlated pair, both columns qualified), C6c (all residual pred column refs are inner-scoped and qualified). Returns `(inner_col, outer_col, non_corr_preds)` or None.
- Canonical C5 set is the tested implementation: `{distinct, group, having, order, limit, offset, with_, joins, TableSample}` (via C5/C5b/C5c/C5d); upstream spec prose from earlier steps defined only `{distinct, group, having, order, limit}` — those are superseded by the code+tests.
- `_try_decorrelate_exists(sql: str)` is the full-query deterministic transform: parse entire `sql` → `copy.deepcopy(tree)` → iterate `list(tree.find_all(exp.Exists))` snapshot → call `_sound_equi_corr_pairs` per node → in-place `exists_node.replace(in_node)` where `in_node = exp.In(this=outer_col.copy(), query=exp.Subquery(this=new_inner_select))` → re-serialize with `tree.sql(dialect="trino")`. Returns the full re-serialized query string if ≥1 rewrite, else None. Any exception → None (fail-safe). Apply locus is the FULL ENCLOSING QUERY AST, not an isolated subquery.
- Pre-pass wiring: `_produce_decompose_candidate` (`mcp_trino/research.py:2005`) calls `_try_decorrelate_exists` at the top of its `try:` block, guarded by `if not run_static_gates:` — advisory path (`run_static_gates=True`) skips and falls through to v51a Priority 4.5 ADVISE unchanged. Returns early `(decorr_sql, [], [], None)` if rewrite succeeds. Dual-path: `trino_query/research.py` imports `_produce_decompose_candidate` from `mcp_trino/research.py` and covers `--direct` path with zero separate wiring.
- Fail-safe invariant: `_sound_equi_corr_pairs` returns None on any unsafe condition → `_try_decorrelate_exists` returns None → pre-pass skips → v51a ADVISE path fires. The rewrite path and the fail-safe path are mutually exclusive and cover the full input space with no third state.
- Row-equivalence gate: characterization test `test_decorrelate_is_row_equivalent_characterization` (line 1535) verifies 7 concrete semantic fixture pairs including NULL outer key, no-match, multiple correlated rows, and non-corr pred preservation. All 7 fixtures confirm result-set equivalence between EXISTS and IN forms.
- Safe-class blacklist completeness rule (process fact): any future blacklist-style safe-class predicate must enumerate coverage by mechanically walking the target expression's `arg_types` dict — NOT by mental enumeration. ## v52 — offline structural critical-path cost model (2026-06-16, main 28248ab)
- New offline analyzer: `genie/skills/mcp_trino/critical_path.py` — `build_cost_tree(sql)` (sqlglot trino) → `compute_costs(root)` → `extract_critical_path(root)` → `analyze_critical_path(sql) -> CriticalPathResult`. Pure offline: ZERO EXPLAIN/cost_reader/plan_cost/network. `analyze_critical_path` never raises (parse error → `available=False` + `reason`). This is the real recursive cost model v51a's name ("critical path") falsely implied — v51a was a single hard-coded advisory string with no computed number.
- New weight table: `genie/skills/mcp_trino/cost_weights.py` — `NODE_BASE_WEIGHT`, `RULE_WEIGHT` (keyed on `rule_ids` ALL_RULE_IDS constants, contract-tested), `severity_multiplier`, `node_penalty`, reducers. Ratio invariants are the contract (cross ≥3× non-equi ≥3× equi); property tests assert RATIOS not absolute values (weights proven perturbation-robust: zero ranking flips across baseline/+30%/5×-compressed in prototype variant C).
- Cost algebra: ordinal row-magnitude propagation by DERIVED-TABLE depth (NOT raw subtree accumulation — that mis-ranks deep nests). `subtree_cost = self_weight*row_magnitude + Σ children + rule_penalties`. Blowups raise magnitude (cross/non-equi join; correlated_subquery = parent_magnitude × inner_cost); reducers (AGGREGATE/DISTINCT/LIMIT_REDUCER, all <1.0) lower it — applied to post-join `derived_magnitude` at critical_path.py ~490/529/547. Invariant: a deeper join of the same type strictly outranks a shallower one.
- bottleneck = highest self-contribution blowup node ON the critical path, NOT `path[-1]` (deepest leaf is often a plain scan inside a correlated subquery). extract_critical_path tie-break is deterministic (stable pre-order among max-weight leaves); ties surfaced as "N tied hot paths".

(v51a's own detection may share this miss — v53 to check.)
