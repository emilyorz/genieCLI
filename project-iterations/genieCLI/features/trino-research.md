# Feature: trino-research

> The `/trino-research` slash command — iterative SQL optimizer that uses MCP-Trino (or direct driver as fallback) to test candidate rewrites against a real Trino server.

## Current capability

- Invoked from `genie chat` as `/trino-research [--file <path>] [--metric <m>] [--iterations <n>] [--runs <n>] [--safe-limit <n>] [--query-timeout <sec>] [--direct] [--diagnose-only] [--help|-h]`.
- Default routing: when `[mcp.trino].enabled = true`, calls into MCP-based execution (`run_trino_research_via_mcp`); `--direct` forces the legacy direct-driver path.
- Pre-launch UX (v22): renders a Plan card showing sql / metric / iterations / verify-runs / server / safety-limit / timeout. v24 added 5-line SQL syntax highlight preview at the top of the card.
- Loop UX (v22-v23): per-iteration status block (`KEPT / WORSE / REVERT / FAIL / SKIP` color-coded) with elapsed time; SQL diff between candidates; live spinner during AI thinking; per-run progress label for verify loops.
- Post-loop UX (v22 + v27): final summary card with baseline vs best bar chart and improvement arrow. v27 dropped the full Optimized-SQL terminal dump — the report file is the source of truth for SQL bodies; terminal stays scannable.
- Report UX (v27): markdown report is iteration-centric — Summary table → compact iteration history table → per-iteration sections (full hypothesis + verdict + mini diff scoped to that round) → single Best SQL block at end. No more triple-SQL duplication. Reports save to `./report/<timestamp>.md` (auto-created) instead of cwd.
- Help (v23 inline + v24 routing): `/trino-research --help` and `/help trino-research` both show the same help card with usage / flags / examples.
- Interactive paste (v35 hotfix): after Ctrl-D, MCP read-only interactive mode shows the metric / iterations / runs prompts before read-only preflight and EXPLAIN sizing, so a slow MCP EXPLAIN no longer looks like paste submission did nothing.
- Safety (v19): preflight gate enforces read-only whitelist + EXPLAIN-based size estimation + row cap; `--safe-limit` opt-in wraps query in `LIMIT n`; default query timeout 300s.
- Write-operation analysis-only mode (v35): `--file` SQL classified as side-effecting (`INSERT`/`UPDATE`/`DELETE`/`MERGE`/DDL including `RENAME` and `REVOKE`/`CALL`/transaction control, plus unsafe multi-statement with writes) is intercepted before execution-oriented optimizer surfaces. It runs offline static analysis plus optional advisory LLM text, saves `./report/trino-research-write-analysis-<ts>.md`, and returns with explicit `SQL executed=no`, `EXPLAIN run=no`, `MCP/Trino reached=no`, `Verified optimization=no`. `--safe-limit` is not applied to write SQL.
- Long-query default (v30 T1): slow baselines now keep tuning by default. `--long-query` remains accepted as a compatibility no-op, while `--no-long-query` restores the directed-report stop path for users who want a diagnosis without further candidate executions. The threshold is still `--long-query-threshold` (default 60s), and `--max-fallbacks` configures the K-retry cap for final L3 row-equivalence verify (default 3).
- Candidate timeout (v30 T2): once iteration starts, candidate / verify runs are capped at the baseline wall-time. MCP path emits best-effort `SET SESSION query_max_run_time = '<baseline>ms'` and also applies the MCP HTTP request timeout; direct path uses Trino cursor `cancel()`. Timeout candidates are marked `timeout_worse` / failed fallback and never replace the current best SQL.
- Long-query report path (v28 T5 + v29 T3): after baseline measurement, if `baseline wall_time > --long-query-threshold` and `--no-long-query` is set, instead of a bare abort the run emits a **directed report** — the baseline's real `peak_memory_bytes` + EXPLAIN (FORMAT JSON) plan cost + static AST findings are turned into ranked optimization directions and rendered to `./report/trino-research-diagnose-<ts>.md`. The baseline has already run; the report skips further candidate executions, EXPLAIN ANALYZE, and the iteration loop.
- Pre-execution diagnosis (v29 T1-T4 + v30 T5): before the first optimization iteration, already-computed diagnostics — static AST findings, SQL shape heuristics, EXPLAIN (FORMAT JSON) plan cost, table partition/sort metadata (MCP path only) — plus the baseline's actual peak memory are folded into a deterministically-ranked `list[OptimizationDirection]` and injected into the optimizer's system prompt. SQL shape heuristics add `materialize-cte-steps` for deep heavy CTE chains and `reduce-raw-rescan` for repeated likely-raw table scans, while keeping CTAS/materialized-view rewrites advisory-only. The LLM optimizes against concrete directions instead of guessing blind. Wired on **both** the MCP default path and the `--direct` path (dual-path symmetry guarded by a regression test). `--diagnose-only` short-circuits before any baseline query and emits the same zero-cost directed report.
- Rule-based gate (v31): before the Trino guide and ranked diagnosis block reach the optimizer prompt, deterministic findings are classified through a shared `RuleGateSummary` into `BLOCK` / `REWRITE` / `ADVISE` / `PASS`. `BLOCK` is non-fatal in v31: it blocks semantic auto-repair, not the CLI run. `REWRITE` is suggest-only and never mutates SQL without the existing result-equivalence guard. `ADVISE` carries Trino field guidance such as CTE step materialization, raw rescan, and memory pressure. Empty `PASS` summaries render nothing. The same shared module feeds MCP default, direct legacy, and long-query plan-cost paths; the HumanSink block is compact (`rule gate  block=N rewrite=N advise=N`) and capped so TUI stays readable.
- Output sinks (v18+ / v30 T1/T3/T4): HumanSink (Rich, colored, no emojis) by default; MachineSink (JSON) when piped. Long-running status spinners include `elapsed=<seconds>s` for baseline, candidate, verify, AI thinking, and EXPLAIN ANALYZE waits. MCP iteration results render as compact blocks: verdict line, metric/delta/elapsed line, optional reason line, optional note line. A fast-but-wrong candidate is visibly explained without forcing the user to parse one overloaded row.
- Configuration (v34): two call-time env knobs tune memory-pressure threshold calibration.
  `GENIE_TRINO_MEMORY_LIMIT_PER_NODE_BYTES` (int bytes, must be > 0): overrides SHOW SESSION
  for per-node memory limit; default = SHOW SESSION `query_max_memory_per_node` or 1 GiB
  fallback; example `GENIE_TRINO_MEMORY_LIMIT_PER_NODE_BYTES=5368709120` (5 GiB).
  `GENIE_TRINO_MEMORY_PRESSURE_FRACTION` (float, range (0, 1]): warning threshold as a
  fraction of the per-node limit; default 0.5; example `GENIE_TRINO_MEMORY_PRESSURE_FRACTION=0.7`.
  Both are call-time: set before `/trino-research`, no restart needed. No effect on `--direct`.

## Design log (append-only)

- **v17:** `/trino-research` hard-requires MCP, no silent fallback. `--direct` is opt-in. Reason: silent fallback hid configuration errors; users were debugging "why is MCP not used" without knowing the path was silently swapping to direct. Alternatives considered: warn-and-fallback — rejected, warnings get lost in normal output.
- **v35:** Write/DDL SQL gets a separate analysis-only mode instead of being forced through the read-only optimizer model. Reason: the existing safety model depends on read-only preflight, EXPLAIN, baseline measurement, candidate benchmarking, optional safe-limit wrapping, and row-equivalence. Those are unsafe or misleading for side-effecting SQL. The v35 implementation classifies `--file` SQL in `chat.py` before MCP config/reachability for write operations; direct entrypoint classifies after SQL acquisition; MCP entrypoint `sql_file`/`sql_text` now classifies before `load_mcp_config()`, `McpClient`, and `list_tools()`. Read-only default MCP behavior remains strict: unreachable MCP still errors and never silently downgrades to offline/direct. Attempt 2 moved classifier/report helpers into import-safe `genie/skills/mcp_trino/write_analysis.py` and added conservative write routing for `EXPLAIN INSERT ...` and `EXPLAIN CREATE TABLE ... AS SELECT ...`; attempt 3 removed the chat startup live MCP probe so slash-command write `--file` analysis can reach the offline guard without MCP.
- **v35 hotfix:** MCP interactive paste now prompts for metric / iterations / runs before running preflight/EXPLAIN. Reason: after Ctrl-D, a slow or hanging MCP EXPLAIN made the UI look unresponsive and hid the selection menu users expected from the direct path. Ctrl-D paste submission now exits prompt_toolkit directly via the current buffer text.
- **v36:** Bad memory-limit env var breadcrumbs now report the final source accurately. Reason: after v34, `GENIE_TRINO_MEMORY_LIMIT_PER_NODE_BYTES=bad` printed "falling through to SHOW SESSION" even if SHOW SESSION also failed and the run actually used the 1.0 GiB fallback. v36 keeps the source behavior unchanged but splits the user-facing line: bad env + usable SHOW SESSION says SHOW SESSION supplied `query_max_memory_per_node=<N> GiB`; bad env + unusable SHOW SESSION says the 1.0 GiB fallback is active. No live cluster numeric validation was performed in v36.
- **v18:** Trino best practices moved from hardcoded Python into `mcp_trino/SKILL.md` body, injected via `parse_skill_md_body() + SkillRegistry.get_instructions(group)`. Reason: tuning the AI's optimization knowledge required code changes; SKILL.md body lets us iterate via markdown.
- **v19:** Preflight gate before any execution. Reason: v18 could OOM on huge result sets, AI could (in principle) emit DML, default 30s timeout was too short for real queries. Triple-defense: read-only whitelist + EXPLAIN size cap + opt-in `--safe-limit` wrapper.
- **v22:** UX overhaul prioritized "make every loop phase legible" over "richer output". Reason: Sam said "希望是有感的提升" — opaque progress() lines were the felt pain. Helpers stay pure (output + kwargs in, nothing else) so they're trivially unit-testable.
- **v24:** MCP status banner runs synchronously at startup with 3s timeout. Reason: simplest path to first-pass visibility; symmetric with `genie doctor`'s probe so users learn one failure mode. Alternatives considered: async background probe — rejected for v24 because Rich console redraw during prompt readline was deemed fragile (revisited in v25).
- **v25:** `_execute_via_mcp` now handles **bare-list response shape** (`[{...}, ...]`) in addition to wrapped (`{"rows": [...]}`). Reason: mcp-trino's actual contract returns a bare JSON list; the previous `data.get("rows", []) if isinstance(data, dict)` silently dropped to empty rows on every query. Side-effect bug fixed at the same time: optimizer's `capture_rows=True` equivalence check was always comparing `[]` vs `[]` → silently treating different SQL outputs as equivalent. Alternatives considered: require all MCP servers to wrap responses — rejected, no standard exists; servers in the wild use both shapes.
- **v25:** `_measure_mcp` now backfills server-side metrics from `EXPLAIN ANALYZE` text when the server's response carries no structured `metrics` dict. Reason: mcp-trino executes the SQL but returns only rows, so `cpu_time_ms`, `peak_memory_bytes`, `processed_rows` were always 0 and the optimizer couldn't rank candidates by anything except wall-clock elapsed. The existing `_parse_explain_stages` already knew how to extract metrics from Trino's text output; reuse it. Cost: 2N queries instead of N when backfill triggers. Alternatives considered: require MCP servers to populate metrics dict — rejected, can't change contract for servers we don't own; transparent backfill keeps both shapes working.
- **v27:** `/trino-research` output UX trio — terminal stops printing the full Optimized SQL (keeps Summary + iteration lines + `Report saved:` pointer), report is rewritten iteration-centric (one Best SQL at the end, per-iteration section with full hypothesis + mini diff + verdict), and report path moves to `./report/<name>.md` with auto-`mkdir`. Reason: Sam's feedback "上次我測試時 有 diff 雖然不錯, 但整個我覺得變得有點混亂" — three pain points in one iteration: 70-line SQL dump on terminal, triplicate SQL in report (Original + Optimized + diff), cwd pollution. Alternatives considered: (a) keep Original as appendix — rejected, doesn't address "三份看三次"; (b) minimal patch (just un-truncate hypothesis) — rejected, rearranges deck chairs; (c) global `~/.genie/reports/` — rejected, Sam explicitly asked for cwd `./report/`. To enable per-iteration diffs the history entries now carry `base_sql` + `candidate_sql`; hypothesis storage no longer caps at 80 chars (only the terminal progress line truncates for display).

On a cluster with `query.max-memory-per-node = 5 GiB`, the effective threshold was 0.5 GiB instead of 2.5 GiB (5× false-positive inflation). **Design decision: env-override is the production path; SHOW SESSION is best-effort.** Most modern Trino deployments removed `query_max_memory_per_node` from session properties (it is now config-only); the genuine per-node value cannot be reliably introspected at runtime. ## Limits (append-only)

- **v17:** Direct-driver path retained but de-prioritized — only invoked under explicit `--direct` flag. Reason: maintaining two execution paths is testing burden. Revisit when: MCP becomes 100% reliable in production AND zero users need direct mode.
- **v18:** SKILL.md body limit not enforced — currently 6KB after v24 expansion. Reason: no measured token-budget pressure yet. Revisit when: SKILL.md body exceeds 12KB OR Trino enhancement runs show truncation.
- **v22:** SQL diff capped at 20 lines with truncation note. Reason: terminal real estate; longer diffs become unscrollable. Revisit if users ask for `--full-diff` flag.
- **v24:** MCP banner probe is synchronous, blocks chat startup for ~3000 ms when MCP is unreachable. Reason: see v24 design log. Revisit: **v26 in flight** — async refactor (deferred from v25 by metric-pipeline hotfix).
- **v26:** MCP-contract testing discipline — when fixing a bug whose root cause is an MCP-server response-shape assumption, the unit test must exercise the **actual server's response shape**, not the convenient default. Concrete failure mode: v25's `13dbfab` shipped a "fix" whose unit test passed (mock returned dict-shaped response), but production failed (real mcp-trino returns bare-list). Sam's office re-run revealed the upstream bug. Mitigation: when adding a test that touches `_execute_via_mcp` or `_fetch_explain_analyze`, prefer `json.dumps([{...}, ...])` (bare-list) over `json.dumps({"rows": [...], "metrics": {...}})` unless specifically testing the wrapped-shape path. Update this note if a third response shape variant appears.
- **v28 T5 (L2 sampled row verify deferred):** Option 3 from PLAN (L1 + L2 + L3) was rejected. L2 would substitute base tables with `TABLESAMPLE BERNOULLI(0.1)` versions and compare rows on the sample before committing to the full L3 verify. Reason rejected: table substitution across CTEs, subqueries, and joins requires a Trino-aware AST parser we don't have (`sqlparse` is shallow), and `TABLESAMPLE` doesn't compose cleanly with aggregations (sum/count change under sampling).
