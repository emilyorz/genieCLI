## What shipped (T1–T3) — full suite **819 passed, 0 skipped**

### T1 — MCP long-query plan-cost parity — P0 (quality-verified APPROVED 9.3/10)

The MCP optimizer ran a REAL `_measure_mcp` on every candidate per iteration; the
`--direct` path already avoided this via `_run_plan_cost_loop`. Added
`_run_mcp_plan_cost_loop` (`genie/skills/mcp_trino/research.py`) mirroring the
direct loop (substituting `_measure_mcp` + the MCP `_results_equivalent`,
returning an `EnhancementReport`), and a dispatch in `run_mcp_enhancement` that
fires only when a real EXPLAIN plan-cost probe succeeds (placed after the v29
`LongQueryAbort` gate-trip, before the baseline EXPLAIN ANALYZE so it is
skipped). Long/expensive queries now rank candidates by EXPLAIN plan cost (zero
real candidate execution) and run real `_measure_mcp` only on the top-ranked
candidates (K-retry on L3 row-equivalence failure). `tests/test_mcp_plan_cost_loop.py`
(6 tests). Codex independently added a correctness upgrade the direct path lacks
(a `row_count` pre-check before `_results_equivalent`, guarding against the
100k-row capture truncation false-passing equivalence).

### T2 — dual-path real-rule_id equivalence test — P0

`tests/test_dual_path_rule_id_equivalence.py` drives the REAL `analyze()` pipeline
with real emitted rule_ids and both `_assemble_mcp_directions` /
`_assemble_direct_directions` UNMOCKED, asserting the non-explain-axis direction
tuples are equal. Regression-guards the v32 rule_id contract. **Verifier note:**
v32 collapsed the two consumer maps into ONE shared `_RULE_KIND_MAP`, so this is
now a thinner guard (no second map to drift); only the headline rule
(`redundant-distinct-after-group-by`) has a pinned expected kind — the other 7
are covered by equality. Cheap strengthening (pin all 8 kinds) deferred to v34.

### T3 — memory-pressure threshold calibration (MECHANISM ONLY — see gap) — P1

`pre_execution_diagnosis.py` gained `_memory_pressure_threshold(peak_memory_limit_bytes)`

- `MEMORY_PRESSURE_FRACTION = 0.5`: when a caller supplies the per-node memory
  limit, the threshold is derived as 0.5 × limit; otherwise the historical 1 GiB
  fallback. Used at BOTH memory-pressure decision sites (explain build-side +
  runtime peak). `bool` guard so `True/False` don't leak as ints. Pure module — no
  live I/O added. Trino doc URLs cited in `sql_static/rules/r1/r2/r6`.
  **KNOWN GAP (honest):** no production caller passes a real
  `query.max-memory-per-node` yet, so **production still uses the 1 GiB fallback**
  — the threshold is now _calibratable_ but not _calibrated_. Wiring it requires a
  `SHOW SESSION` round-trip + Trino data-size parsing that should be validated
  against a real cluster (Sam's office cluster), not mocked blind. **This is the #1
  v34 follow-up**, not a silent deferral.

Review caught real substance: the L1-structural test's tautology risk (resolved by confirming `plan_signature` encodes table identity); Codex's row_count correctness upgrade; the T3 wiring gap (production still 1 GiB); the partial-EXPLAIN cost distortion carried in both paths.

### Failed

- **First Codex attempt (full V3 PLAN authoring) stalled ~30 min** in the telemetry-compliance rabbit hole and produced nothing — the same ceremony that dead-locked the Claude sessions. `promote ⭐ P1 M — strict-V3 telemetry is the bottleneck for ad-hoc iterations on BOTH runtimes; reserve it for codex-runner-driven iterations; ad-hoc work runs hooks-off + dispatched review + an archive record.`
- **T3 shipped as an unwired mechanism** (production still 1 GiB). `promote ⭐ P1 S — wire query.max-memory-per-node on the MCP path and validate against a live cluster (v34 #1).`
- A codex-rescue dispatch reported "completed" while only having _launched_ a background codex job — a false-done. `park age 1/3 — trigger: a backgrounded executor's false-done causes an unreviewed change to be treated as final.`

### Change next

- Scale the second (opus) quality gate to risk: full double-review for production-path refactors (T1), spec+orchestrator for tests/pure-const changes (T2/T3) — record the scaling decision explicitly (done here).
