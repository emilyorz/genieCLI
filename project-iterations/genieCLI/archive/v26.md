## Process gap

- **Didn't read the E2E test script before reading its output.** For three weeks I treated `research-e2e.json`'s `kept` / `imp` fields as product metrics, not realizing `noop_build_prompt` made them mechanically zero. The 2026-04-18 `FAIL` alert was a chance to re-audit the test's intent, but I patched the signature and moved on. SKILL.md's VERIFY code-track says "tests pass, diff reviewed" — it does not say "and confirm the test still measures what its name suggests". That's the gap.
- **Ledger state machine has no forcing function for closing a round.** v26 sat at "Todo empty, retro tbd" for 2 days because nothing pinged me. Sam's "先這樣" is a product decision, not a process closure signal. I read it as "stop working" when I should have read it as "write retro and open v27".

## Do differently next time

- **Before trusting an E2E output, `git log -p -1 -- <script>` first.** Specifically check whether `build_prompt`, `model`, `verify_runs`, or any threshold fields have been muted, stubbed, or loosened. If they have, treat the output as pipeline-only signal and say so when reporting.
- **Closing retro is triggered by "Todo empty", not by "Sam asked for next thing".** When the last Todo flips to done, write retro the same session, even if no new work is queued. If Sam's next ping is ≥24h away, v26 should already be archived and `STATUS.md` pointing at v27.
- **When a test FAILs on a signature mismatch, read the caller one level up before patching.** The 4-18 `*args, **kwargs` widening worked to unblock, but `noop_build_prompt` itself should have flagged "why is this a noop on a test whose output I treat as a product metric?"
