## What changed

### Timeout docstring

`genie/skills/mcp_trino/preflight.py` now describes the actual implementation:
`make_query_max_run_time_sql()` delegates to `make_candidate_timeout_ms()`,
which uses `CANDIDATE_TIMEOUT_HEADROOM` (currently 2x) and clamps tiny baselines
to at least 2000ms.

No behavior changed.

### Bad env breadcrumb

`genie/skills/mcp_trino/research.py` now distinguishes two
`bad_env_fallthrough` outcomes:

- bad env + usable SHOW SESSION: the progress line says SHOW SESSION supplied
  `query_max_memory_per_node=<N> GiB`;
- bad env + unusable SHOW SESSION: the progress line says SHOW SESSION did not
  provide a usable `query_max_memory_per_node` and that the 1.0 GiB fallback is
  active.

The source-tag behavior did not change.

### Executable T-F-24 coverage

`tests/test_per_node_memory_limit.py` now makes the intended branch unavoidable:

- supplies EXPLAIN JSON estimates for `EXPLAIN (FORMAT JSON)`;
- uses a long 61s fake baseline so MCP plan-cost mode is entered;
- removes the old conditional assertion;
- asserts `_run_mcp_plan_cost_loop` was called and received
  `peak_memory_limit_bytes == 5 * 1024**3`.

The same test file also adds bad env + failed SHOW SESSION breadcrumb coverage.
