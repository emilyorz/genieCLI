### Residual #1 — memory-pressure threshold live wiring (closes v33 T3 known gap)

The v33 `_memory_pressure_threshold` function accepted a `peak_memory_limit_bytes` argument
but every production caller passed `None` — the threshold always fell back to the hard-coded
1 GiB. On a cluster with `query.max-memory-per-node = 5 GiB`, the effective threshold was
0.5 GiB instead of 2.5 GiB: a 5× false-positive inflation.

**New in `genie/skills/mcp_trino/research.py`:**

- `_TRINO_DATASIZE_UNITS` + `_parse_trino_datasize(s)` — pure DataSize parser, binary base
  (1 kB = 1024 B, Sam-locked). `math.isfinite` guards at both `val` and `product` prevent
  `float("1e400")` overflow raising. Returns `None` on zero, empty, garbage, or unknown unit.
  Distinct from the inline EXPLAIN-ANALYZE unit map at `:495` (not touched).
- `MemoryLimitResult(bytes, source)` NamedTuple — source-tagged result from the fetch helper.
- `_fetch_per_node_memory_limit(client) -> MemoryLimitResult` — resolves per-node limit once
  per `run_mcp_enhancement` call, three-source priority:
  1. `GENIE_TRINO_MEMORY_LIMIT_PER_NODE_BYTES` env var (no SHOW SESSION round-trip when set)
  2. SHOW SESSION `query_max_memory_per_node` — genuine per-node; `query_max_memory` (total
     budget) intentionally never read (would make threshold N× too permissive)
  3. `None` → 1 GiB fallback (no regression from v33)
  Bad env var falls through to SHOW SESSION (`source="bad_env_fallthrough"`), not
  straight to `None`. Row-key normalization (`.lower()`) handles `Name`/`name`
  casing. `value → default` column fallback (D08). `except Exception: pass` outer guard.
- Five call sites threaded: `_assemble_mcp_directions` (4 sites, kwarg `peak_memory_limit_bytes`)
  and `_run_mcp_plan_cost_loop` (1 site, kwarg). Single fetch before the `--diagnose-only`
  branch at `:1601` — no per-iteration SHOW SESSION round-trips.
- One `output.progress` breadcrumb line per run showing limit source (env / show_session /
  bad_env_fallthrough / default-fallback).
- `_assemble_mcp_directions` docstring corrected from "three MCP call sites" to "four".

**New in `genie/skills/mcp_trino/pre_execution_diagnosis.py`:**

- `import os` (stdlib, no alias), `import math`.
- `_resolve_memory_pressure_fraction() -> float` — reads `GENIE_TRINO_MEMORY_PRESSURE_FRACTION`
  at call time; `math.isfinite` guard + `<= 0` / `> 1` clamp to default 0.5.
  `MEMORY_PRESSURE_FRACTION = 0.5` constant kept (referenced by existing tests).
- `_memory_pressure_threshold` now calls `_resolve_memory_pressure_fraction()` instead of
  using the constant directly.

**New in `genie/chat.py`:**

- "Environment variables" section added to `_print_trino_research_help`, documenting both
  knobs with type, range, default, example, and `--direct` asymmetry note.

**New test files:**

- `tests/test_trino_datasize_parser.py` — 20 parametrized cases (A/B series: valid formats,

- `tests/test_per_node_memory_limit.py` — 33 cases (env override, SHOW SESSION, source labels,

## RETRO

### Worked

- **Explore back-edge caught the total-vs-per-node inversion before any code.** Attempt 1
  proposed `query_max_memory` (N× too large) as the SHOW SESSION source; reviewer rejected
  it as inverting the signal. Redesign locked `query_max_memory_per_node` and added a
  mandatory invariant comment. Front-loaded discovery at its best.
- **Review→develop back-edge caught the nan ValueError before commit.** MAJOR-1 was a
  genuine correctness defect (documented "never raises" violated by `float('nan')` input)
  found post-suite-pass, pre-ship. Back-edge worked.
- **Single-fetch architecture and source-tagging (MemoryLimitResult) were the right design.**
  Source tagging resolved the bad-env ambiguity cleanly; single fetch before the
  diagnose-only branch ensured all 5 sites get the same value without N× round-trips.
- **TLV4 flat SDD ran to DONE without ceremony blockage.** v33 dead-locked 3 Claude sessions
  and 1 Codex in strict-V3 telemetry before producing anything. v34 shipped in one day with
  two productive back-edges.

### Failed

- **Explore attempt 1 used the wrong SHOW SESSION property.** `query_max_memory` vs
  `query_max_memory_per_node` is a fundamental semantic error. A one-line sanity check
  ("is this value per-node or total?") before writing the design up would have prevented it.
- **Ticket attempt 1 had a self-contradiction in A3 (bad-env fallthrough).** Source
  `"bad_env_fallthrough"` AND `bytes=None` are mutually contradictory when SHOW SESSION
  succeeds. Caught by the ticket reviewer before code was written.
- **Develop attempt 1 shipped without nan coverage.** 46 ticket-specced test cases passed
  but the spec never included non-finite inputs for `_resolve_memory_pressure_fraction`.
  The reviewer found the gap; T-F-27 through T-F-30 closed it in attempt 2.
- **T-F-24 threading assertion is conditional and never fires.** Pre-ship known gap; carried
  as residual.

### Change next

- Any function described as "never raises" or "failure-safe" in the Ticket §Test list must
  include at least one non-finite / overflow case.
- Explore steps involving Trino session properties should include an explicit "is this
  value per-node or cross-cluster?" sanity check before advocating a property as a source.
