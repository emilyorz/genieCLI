## Goal

Close the directed-optimization loop and repair the deterministic layer that
feeds the AI: (1) fix the rule_id contract that silently disabled v31's rule-gate
`REWRITE` class, (2) keep the diagnosis fresh per iteration, (3) make "directed >
blind" measurable.

## What shipped (T0–T2)

### T0 — rule_id contract repair (the prize) — P0

The 8 sqlglot rules emitted ids (e.g. `redundant-distinct-after-group-by`,
`predicate-not-pushed-to-cte`) that **neither** `rule_gate._STATIC_ACTIONS`
**nor** `pre_execution_diagnosis._RULE_KIND_MAP` keyed on — they keyed on stale
guesses (`distinct-after-group-by`, `predicate-pushdown`, …). Consequence: every
mismatched rule fell through to a generic `advise`; v31's `REWRITE` action class
**never fired in production** (`rewrite=` count was always 0), and the gate tests
passed only because they fed _fabricated_ rule_ids (tautological).

- NEW `genie/skills/trino_query/sql_static/rule_ids.py` — canonical id constants
  - `ALL_RULE_IDS`, imported by all 8 producers + both consumer maps (drift is
    now a `NameError`, not a silent mis-classification).
- `rule_gate._STATIC_ACTIONS` + `pre_execution_diagnosis._RULE_KIND_MAP` re-keyed
  on the constants; keys now exactly equal `ALL_RULE_IDS`.
- Unknown rule_id is now **loud** (`logger.warning`) then fails open to advise.
- Replaced the tautological tests; added `tests/test_rule_id_contract.py` (real
  `analyze()` → `build_rule_gate_summary` asserting `REWRITE` actually fires).
- **Evidence:** before fix `redundant-distinct-after-group-by` → `advise`,
  rewrite=0; after fix → `REWRITE`, rewrite=1.

### T1 — per-iteration re-diagnosis — P0 (both paths)

Diagnosis was computed once before iteration 1 (describing the original SQL) and
went stale after the LLM rewrote the query → the optimizer was effectively blind
from iteration 2. Now: when `best_sql` changes, re-diagnose the current query at
zero query cost (static + EXPLAIN FORMAT JSON; table metadata reused via a new
optional `table_metadata` arg on `_assemble_mcp_directions`) and inject the fresh
directions into that turn's context. SQL-hash cache so a stable `best_sql` is not
re-diagnosed. Wired on both `mcp_trino/research.py` and `trino_query/research.py`.

- **Test:** `tests/test_per_iteration_rediagnosis.py` drives the real `--direct`
  loop for two iterations and asserts iteration 2's context carries a fresh
  `fix-select-star` direction that only a re-diagnosis of the changed `best_sql`
  could produce.

### T2 — observational direction efficacy — P0 (both paths)

After the run, compare each diagnosed direction's `target_metric` between
baseline and best; mark `observed_moved`; directions sharing a metric are
`co_attributed` (no per-direction causal claim). Rendered to the user on both
paths. Pure helpers `attribute_directions` + `format_attribution_report` in
`pre_execution_diagnosis.py`.

- **Test:** `tests/test_direction_efficacy.py` (6 unit tests: moved / not-moved /
  missing-metric / co-attribution / empty / render).

## RETRO

### Worked

- The rule_id repair revived a shipped-but-dead feature with a bounded, low-risk
  change (constants + re-key) and a real end-to-end test that forbids the
  fabricated-id tautology that hid the bug.
- Per-iteration re-diagnosis and observational efficacy both landed dual-path
  (v28/v29 discipline) and were each behaviourally tested.

### Failed

- **The strict-V3 live-hook bootstrap dead-locked a Claude-Code session three
  times** (runtime handoff codex→claude-code orphaned telemetry; an incomplete
  CURRENT.md left the guard blocking the very edits needed to fix it). Recovery
  each time required an external shell. `promote P1 M — a Claude-Code-driven
V3 iteration must author CURRENT.md atomically (one complete guard-valid write)
or run hooks-off as a documented deviation; never bootstrap incrementally.`
- **v32 shipped without a formal ledger** (this file is the retroactive fix).
  `park age 1/3 — trigger: a future out-of-process hotfix ships to main without
a same-day archive record.`
- MCP-path T2 efficacy has only unit + mirror coverage (no MCP loop integration
  test, because the existing wiring tests short-circuit before the loop).
  `park age 1/3 — trigger: an MCP-path efficacy regression slips a release.`

### Change next

- When a Todo's headline property is dual-path symmetry, the unmocked
  cross-path equivalence test is a Step-6 Tkt Verify line (carried from v29; T3
  below still owes the real-rule_id version). `promote P1 S`.
- Re-run pytest and quote the literal figure for every test-count claim (809).

### Process gap

- Strict-V3 with **live hooks** is hostile to incremental ledger authoring by a
  Claude-Code session: any intermediate incomplete CURRENT.md blocks the edits
  needed to complete it, and the sanctioned recovery (dispatch wrapper, ledger
  edits) is itself gated. The codex runner does not hit this (runtime matches,
  ledger authored atomically). Until a Claude-Code-safe bootstrap exists, drive
  Claude-Code iterations either atomically or hooks-off-with-deviation.

### Do differently next time

- Before starting a Claude-Code V3 iteration, decide up front: **atomic
  CURRENT.md** (write the whole guard-valid ledger in one pass) **or hooks-off
  deviation** — and never switch the activation `runtime` mid-iteration (it
  orphans existing telemetry and hard-blocks every tool).
