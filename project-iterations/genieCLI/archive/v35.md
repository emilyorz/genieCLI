# v35 — `/trino-research` Write-Operation Analysis-Only Mode

## Status

- Runtime: Task-Ledger-V4 Codex run.
- Commit: lands with the v35 feature commit.
- State: V4 reached DONE after Develop attempt 3, Review, Wrap/Retro, and final reconcile.
- Scope: `/trino-research` write/DDL SQL must get offline advisory analysis instead of entering execution-oriented optimizer paths.

## What Changed

- Chat `/trino-research --file <sql>` now reads and classifies file SQL before MCP config load, `McpClient` construction, or `list_tools()` for write operations.
- Direct `run_trino_research()` now classifies after SQL acquisition and empty-SQL guard, before metric prompts, direct EXPLAIN runner construction, `_run_optimization_loop()`, `_measure()`, or `_execute_sql()`.
- MCP `run_trino_research_via_mcp()` now reads `sql_file`/`sql_text` and classifies write SQL before `load_mcp_config()`, `McpClient`, or `list_tools()`. Read-only SQL then continues through the existing strict MCP reachability path.
- Shared classifier/report helpers live in import-safe `genie/skills/mcp_trino/write_analysis.py`, which does not import MCP client/config or direct Trino execution modules at top level.
- Classified write SQL produces `./report/trino-research-write-analysis-YYYYMMDD-HHMMSS.md`.
- Report states `Mode=write-analysis`, `SQL executed=no`, `EXPLAIN run=no`, `MCP/Trino reached=no`, `Verified optimization=no`, and `Advice status=advisory, unverified`.
- `--safe-limit` on write SQL is not applied and is explicitly called out in the report/summary.

## Classifier Coverage

Positive write classifications:

- CTAS: `CREATE TABLE ... AS SELECT`, `CREATE OR REPLACE TABLE ... AS SELECT`.
- DML: `INSERT`, `MERGE`, `UPDATE`, `DELETE`, including CTE-leading write forms.
- DDL / privilege control: `CREATE`, `DROP`, `ALTER`, `TRUNCATE`, `RENAME`, `GRANT`, `REVOKE`.
- Other side effects: `CALL`, `COMMIT`, `ROLLBACK`.
- Unsafe multi-statement SQL containing any write keyword, including explicit `RENAME` and `REVOKE`.

Read-only preservation:

- `SELECT`, `WITH ... SELECT`, `SHOW`, `DESCRIBE`/`DESC`, `EXPLAIN SELECT`, and commented-out write keywords followed by read-only SQL remain non-write and continue through existing read-only routing.
- Default MCP read-only behavior remains strict: unreachable MCP still errors; no offline/direct fallback was added.

## Implementation Notes

- Attempt 2 moved the classifier/report helper out of `mcp_trino/research.py` into `genie/skills/mcp_trino/write_analysis.py` to satisfy the import-safe offline-module contract.
- Attempt 3 removed the chat startup live MCP probe, so slash-command write `--file` analysis can reach the offline guard without requiring MCP config/client/list_tools first.
- `EXPLAIN INSERT ...` and `EXPLAIN CREATE TABLE ... AS SELECT ...` now classify conservatively as write-analysis, while `EXPLAIN SELECT ...` remains read-only.
- Tests were added to the allowed existing files:
  - `tests/test_run_loop_mode_dispatch.py`
  - `tests/test_mcp_research.py`
- Import-safety coverage uses an isolated Python subprocess to prove importing `genie.skills.mcp_trino.write_analysis` does not load `genie.skills.mcp_trino.client`, `genie.skills.mcp_trino.research`, or `genie.skills.trino_query.connection`.
- Interactive default MCP paste was intentionally not refactored in v35. MCP-offline write-analysis is guaranteed for `--file` and entrypoint `sql_file`/`sql_text`; default MCP paste may still hit MCP reachability before paste acquisition.
